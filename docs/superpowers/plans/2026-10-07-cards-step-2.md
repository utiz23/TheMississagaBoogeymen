# Step 2: Card redesign (10 themes) on the preview page

## Context

The operator handed off a collectible player-card design: `PlayerCard.dc.html` plus `card-data.js`, in `docs/design/handoffs/2026-10-cards/`. It has 10 themes across 6 tiers, a front/back flip, and animated mythic effects.

Step 1 (branch `feat/player-cards`, local only) already computes each player's **tier, level and badges** into `player_card_progress` / `player_badge_levels`.

Step 2 renders the new card from that data. Per the spec's **Test run**, it renders **only on the dev preview page** `/preview/roster/[id]`. Nothing deploys until the final switch.

Spec: `docs/superpowers/specs/2026-10-07-player-cards-badges-design.md` (Part 2, D7–D9).

**Operator decisions (this session):**

- **Two rounds.** Round 1 is the card itself (front and back) plus the 5 regular themes (Away, Home, Alternate, Carbon, Hardlight), shown in the preview hero, a gallery and a card row. Then a review. Round 2 is the 5 mythic themes (Frozen, Cyber, Inferno, Storm, Maximus) with shrunk assets.
- **Hero hook.** Add an optional `portrait?: ReactNode` prop to the shared `ProfileHero`. The live page passes nothing, so its output stays identical, and an HTML diff proves it.

**Spec vs prototype: follow the prototype**, and list these for the operator at the round-1 review:

- Front has **no level pips**; level shows in the back header.
- Flip takes **650 ms** with `cubic-bezier(.3,.7,.3,1)`.
- The back is a **3-row ledger**: LAST 10 / current title / CAREER. Then "BADGES n / pool earned" with the top 4 badges. No bio, since there is no data for it.
- Goalie front stats are GP SV% GAA W.
- DNF counts as a loss in last-10, matching the site rule. Today's hero `aggregateLast10` does not, so the two will disagree.
- Platform and flag use the site's existing `PlatformIcon` / `NationalityFlag`, not the prototype's hardcoded xbox/US SVGs.

## Approach

### Round 1, part A: data and pure core (TDD, each step committed)

1. **Theme and badge helpers.** New `packages/db/src/cards/card-theme.ts`, exported from `cards/index.ts`:
   - `resolveCardTheme(tier, mythicTheme)` uses `TIER_THEME` for tiers 1–5. Tier 6 takes the mythic theme, falling back to `futureB`.
   - `pickBestBadge(rows)`: level > 0 only, highest level wins, ties go by `BADGE_FAMILY_IDS` order.
   - `isThemeUnlocked`.
   - Tests in `card-theme.test.ts`.
2. **Batch query.** `getCardProgressForPlayers(ids)` in `packages/db/src/queries/cards.ts`:
   - One query: `player_card_progress LEFT JOIN player_badge_levels ON player_id AND level > 0 WHERE player_id IN (…)`, grouped in TS with the helpers above.
   - Returns `Map<id, {tier, level, theme, bestBadge}>`. Empty `ids` returns an empty map with no query.
   - A player with no row gets T1 / L1 / `away` in the adapter.
   - This also closes the step-1 follow-up "add getCardProgressForPlayers".
3. **Theme generator.** `docs/design/handoffs/2026-10-cards/port-card-themes.mjs`, same eval pattern as the existing `port-badge-skins.mjs`.
   - Emits GENERATED `apps/web/src/components/cards/card-themes.ts`: all 10 themes plus `CARD_TIER_STYLE` (chip and silhouette size from `TIERS`).
   - Merges `posInk` and the `tk` defaults.
   - Drops the dead keys (`texture unlockBg hud crack noCrack fire flame`).
   - Rewrites asset paths to `/images/cards/*` (a broad regex covering png/gif/webp/avif and bare strings).
   - Output satisfies a hand-written `card-theme-types.ts`. Run `prettier --write` on it, and check that running the generator twice produces the same file.
4. **View model and adapters.** `apps/web/src/components/cards/card-model.ts` and `card-adapters.ts`.
   - `CardViewModel = { front: CardFront; back: CardBack | null }`.
   - Front: name, jersey, role, position tag and colour, record, win %, 4 stats with the lead in slot 4, platform, nationality, tier, level, theme, badge.
   - Back: ledger head and rows, badges `{earned, pool, top[≤4]}`, source label.
   - Pure builders:
     - record and win % (`'—'` when missing);
     - stat cells for both roles;
     - `buildLast10`: role filter, at most 10 games, DNF counts as a loss; goalie SV% = saves / (saves + GA);
     - ledger: current title = the career row matching `currentEaSeason`; CAREER appears only with 2 or more rows;
     - badge showcase.
   - Adapters:
     - `cardFromRosterRow(row, progress?)` takes a structural `CardRosterRow` that `getEARoster`/`getRoster` rows satisfy. Role = `preferredPosition ?? favoritePosition ?? position`.
     - `cardFromProfile({overview, career, progress, role})` uses `overview.currentEaSeason`, `overview.trendGames`, `getPlayerCareerSeasons` rows and `selectedRole`. The hero needs no new query.
   - **No runtime import of `@eanhl/db/queries`** in these modules (type-only), because it would pull the db client into the client bundle.
5. **Style mapping.** `card-style.ts`:
   - `themeVars(theme, tier)` returns `--pcard-*` custom properties: background with the gradient rim (`padding-box` layers plus a `border-box` rim and a transparent border), border and shadow in normal and hot states, rule, text tokens, plates, chip.
   - `layoutVariant(theme)`.
   - `resolveFx(theme, tier, {motion, hot})`, a direct port of the prototype's `mo()` gates. Foil only at tier ≥ 4 and not on Inferno; pulse at tier ≥ 2 or when hot.
   - `fx-geometry.ts`: the prototype's seeded LCG shapes, precomputed once at module load (hydration-safe).

### Round 1, part B: card shell and the 5 regular themes

6. **Card shell.** `apps/web/src/components/cards/player-card.tsx` (`'use client'`), `card-front.tsx`, `card-back.tsx`, `player-card.css`.
   - **Naming:** classes `.pcard*`, variables `--pcard-*`, keyframes `pcard-*`. This avoids clashes with the live global `.hpc*` classes and the hero's `--pc-w`.
   - **Structure:** wrappers outer (hover lift) → tilt (ref-driven: `perspective(900px) rotateX(-y·10) rotateY(x·12) scale(1.02)`) → flip.
   - Props: `card`, `context: 'hero' | 'list'`, `href?`, `active?`. It flips only in `hero` context, by click or Enter/Space.
   - Front footer: `<Badge size={34}>` from step 1. Back: the top 4 badges at size 30.
   - Build `home` end to end first, then **spike the flip on phone and Safari** (keep `overflow`, `filter`, `mask` and `isolation` off the 3D wrappers).
7. **Themes and motion.**
   - Port `away`, `alternate` (gloss, clip-paths), `carbon` (bevel, plates) and `futureB`/Hardlight (`fx/hardlight.tsx`: static grid plus SMIL grid and `pcard-scan`).
   - `fx/foil.tsx`, the pulse, and the hover sweep (CSS on `[data-hover]`).
   - `use-card-motion.ts`: `motionOn = !reducedMotion && inView && !document.hidden && (context === 'hero' || hot)`, where `hot = hover || active`.
     - Reuse `useReducedMotion` from `apps/web/src/components/matches/motion.tsx`. It starts as `true`, so SSR is safe.
     - New `useInView` with IntersectionObserver and a 200px margin.
   - When motion is off, render the prototype's static fx variant; don't just pause it.
   - Safety net: `@media (prefers-reduced-motion: reduce)`.
   - SVG ids come from a sanitized `useId()`. No `Math.random` or `Date` during render.
8. **Preview wiring.** Live components are untouched apart from the hook.
   - **`ProfileHero`** (`apps/web/src/components/roster/profile-hero.tsx`): add the optional `portrait` prop and render `{portrait ?? <PortraitCard>…existing…</PortraitCard>}` inside `.ph-col-portrait`. Prove `/roster/3`'s HTML is unchanged with a curl diff before and after, build hashes stripped.
   - **Preview page** (`apps/web/src/app/preview/roster/[id]/page.tsx`): pass `portrait={<PlayerCard card={cardFromProfile(…)} context="hero" />}`.
   - **Gallery** (new private folder `apps/web/src/app/preview/_cards/`, deleted at the switch): `card-gallery.tsx` shows the player in all 10 themes. In round 1 the 5 mythics are labelled "Round 2" placeholders.
   - **Card row:** `preview-card-carousel.tsx`, a copy of `PlayerCarousel` that uses the new card and the unmodified live `player-carousel.css`. Data: `getEARoster(titleId)` plus `getCardProgressForPlayers`.
   - **Depth-chart check:** a 3-card strip at `zoom: .66`, to catch zoom-plus-3D problems early.
   - **Dev-only URL params:** `?cardTheme=&cardTier=&cardLevel=&face=back&gallery=0`.

**→ Round-1 review with the operator.** Go through the conflicts listed above and gather tweaks.

### Round 2: the 5 mythic themes

9. **Asset pipeline.** `docs/design/handoffs/2026-10-cards/make-card-assets.sh` writes to `apps/web/public/images/cards/` from `Card Customization Page.zip`.
   - **Stills:** ffmpeg → WebP at 860px tall, q≈72. `fx-future-mask` → WebP with alpha. `ice-cracks.avif` kept as is.
   - **Rain GIF** → cropped animated WebP.
   - **Embers GIF** → cropped VP9 WebM plus H.264 MP4. Screen blend makes black transparent.
   - **Lightning `tex-storm-live.webp`:** split it into frames with Pillow (ffmpeg 6.1 can't decode animated WebP), then cropped WebM plus MP4 with `-g 15`.
   - Unused assets are dropped: `fx-inferno-fire.gif`, both bolt PNGs, `tex-inferno-cracks`.
   - `card-assets.ts` lists the files. `card-assets.test.ts` checks:
     - per mythic: stills + Σ max(webm, mp4) ≤ 800 KB;
     - total ≤ 3 MB;
     - every listed file exists;
     - nothing in the folder is unlisted.
   - Expected total is about 1–1.3 MB.
10. **Effects**, from easiest to riskiest, each with its static variant:
    1. `fx/frost.tsx`: snow, twinkle, frost breath, ice panel.
    2. `fx/olympus.tsx`: rays, halo, motes, gilded rim, meander band.
    3. `fx/cyber.tsx`: circuit mask and traces.
    4. `fx/inferno.tsx`: embers `<video>`, rune sigil, flicker, gilded rim.
    5. `fx/storm.tsx` plus `use-storm-strike.ts`:
       - A `setTimeout` chain (rain for 6–16 s, then a strike for 1–2 s) runs only while motion is on.
       - It toggles `data-strike` through a ref, with no re-render, and seeks and plays the lightning video.
       - Rain, the electric rim and the arcs come from CSS.
       - If the `feTurbulence` rim is too heavy on a phone, filter only the static rim rect.
    - Video and animated-WebP elements mount **only while motion is on**, so nothing downloads otherwise.
    - Write both mask-composite syntaxes. Swap `visibility` on each face partway through the flip, so effects don't bleed through in Safari.
    - Gallery placeholders become the real mythic cards.

**→ Round-2 review**, including a phone pass over Tailscale.

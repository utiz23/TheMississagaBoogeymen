# News desk bots release 1 — build rulings and deferred items

**Status:** record of the subagent-driven build of `2026-10-26-news-desk-bots.md` (branch `feat/news-desk-bots`, finished 2026-10-26).
Each ruling is a decision Claude made during the build, with its reason and what it costs if wrong. The operator can reverse any of them.
Superseded: ruling 39 (notes matched by name) is replaced by ruling 41 (by player id); ruling 43 (rules version stays .4) was later bumped to 2026-10-26.5 in the final fix wave.

51. Ruling (T2, 2026-11-13, Lead): reverses ruling 10's sub-case. When the judge's verdict parsed but its reply line failed the code check or the review after all tries, the model's verdict (usable / joke / unusable) is KEPT, no follow-up is asked, and a short neutral line from the reporter's own fallback pool is posted. Only when there is no verdict at all (the call threw, was refused, or never parsed) does it fail closed to unusable. Reason: real game 3440, a usable answer was stored unusable because the closing line missed the review. Cost if wrong: a verdict that the model gave with a rejected reply line is trusted.
52. Ruling (T2, 2026-11-13, Lead): ASK_MAX_WRITES 2 -> 4; a failed write logs its reason (never the player's answer: the player's word runs are redacted); fallback lines come from a pool of 4 per reporter and kind (question, closing, acknowledgement), never the same line twice in one scrum thread while the pool lasts (the used lines are kept per process). Cost if wrong: about 2 more model calls on a failing question or judgement.
53. Ruling (T2, 2026-11-13, operator via Lead): supersedes ruling 49's echo rule. A pop-up answer is echoed in the thread right after the submit, before the judgement, for every verdict. The only exception is an answer the code refuses (it names a "Leave me out" or forbidden person, the player left the sheet, or the sheet is not known). Typed answers are already visible. The desk still never quotes an unusable answer later. Cost if wrong: an unusable answer stays visible in the thread.
54. Ruling (T2, 2026-11-13): `/gm ask` is stored in its own table `news_gm_asks`, not as a `news_gm_notes` row. A note reaches the writers as a true event of the night; a question is not an event. Cost if wrong: one more table.
55. Ruling (T2, 2026-11-13): the panel and the round's target are made lazily at a person's first question (not when the person row is inserted), so every way to join a scrum (auto pick, Talk, /scrum, /gm note, /gm ask) shares one code path. An old person (a question already asked, no panel) keeps the one-reporter rules.
56. Ruling (T5, 2026-11-13): rule C ("no crude quotes") treats the swear words of the desk's strong list, slurs and a few other crude words as crude; the mild words hell, damn and crap are NOT crude (the three swearing reporters use them, and a player's mild word could always stand in a quote). Cost if wrong: a quote with "damn" is printed; the operator can tighten the list in `news/crude.ts`.
57. Ruling (T5, 2026-11-13): hard lines use a separate cheap model check (`hard-lines.ts`) that runs BEFORE the claim and the pop-up echo, not only the judge's `offlimits` class: the echo comes before the judgement (ruling 53), so only an earlier check can keep an off-limits answer out of the thread. The judge keeps `offlimits` as a second line (it then takes the echo down and reopens the question). Cost if wrong: one extra small model call per player answer.
58. Ruling (T5, 2026-11-13): the check fails closed, also when the extras budget is spent: an answer in flight at the 80% stop gets no reaction instead of the old fixed "unusable" line. Cost if wrong: a player's last answer of the month is not acknowledged.
59. Ruling (T5, 2026-11-13): "real people outside the club" does not cover a plain hockey remark about a pro player, coach or team; an insult or a private-life remark about one does. Reason: the players talk about pro hockey all the time. Cost if wrong: a harmless NHL reference gets an answer; tighten the prompt in `hard-lines.ts` if the operator wants every real name off-limits.
60. Ruling (T5, 2026-11-13): feud points: mild insult 1, strong 2; half-life 7 days (Lead); levels simmering 2, feud 5, open war 10; total capped at 12; the insult goes to the reporter the message names, else to the reporter asked. Reason: one strong insult is a simmer, three in a few days are a feud, only a sustained campaign is a war; the cap stops a spam night from growing into a month-long war. Cost if wrong: feuds start too early or too late; the numbers live in `packages/db/src/news/feuds.ts`.
61. Ruling (T5, 2026-11-13): a message in a press thread that is NOT an answer counts for feuds by a code check only (a reporter's name plus a rude word; no model call), and only in a scrum or interview thread (`isPressThread`). Cost if wrong: a few insults are missed, or one unlucky word match adds a point.
62. Ruling (T5, 2026-11-13): a reply to a wire post is checked before the 50% chance gate, so a reply the reporter would not answer still counts for the feud and still gets the hard-line check. Cost if wrong: one small call for each reply, answered or not.
63. Ruling (T5, 2026-11-13): feuds are flavour, so a feud that cannot be read or written never stops a question, an answer, a recap or a column (no points, level none, one log line). The hard line is the opposite: it fails closed. Cost if wrong: a feud that does not show for a while.
64. Ruling (T5, 2026-11-13): the recap and the column use only the writing reporter's own feuds (at feud level and above, players at "Go easy" never) and at most two; the review is told they are that reporter's view. Cost if wrong: a feud of another reporter is not told that night.

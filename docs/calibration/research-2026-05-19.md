# Calibration Loop for an Offline Sports Video OCR Pipeline

## Chevron-to-event matching algorithm

**Question.** Should chevron matching move to event-first, clock-aware clustering, or a hybrid?

**Synthesised answer.** The literature points quite clearly toward **event-first as the primary path, with clustering only as a recovery path**, not the other way around. In multi-object tracking, identity switches become common when association is driven by a weak cue alone; that is exactly why Deep SORT replaced plain overlap-based association with a stronger cost that combines motion and appearance, and why it uses explicit frame-by-frame assignment rather than letting identities emerge from spatial proximity alone. ByteTrack pushes the same idea further by **associating high-confidence observations first** and then using lower-confidence observations only as a second-pass recovery mechanism, which is a very close analogue of your "selected highlight is reliable, cross-frame cluster is statistical" setup.

That makes **clock-aware clustering alone a partial fix, but not the best architectural move**. Adding clock distance into the cluster key will reduce some bad merges, but it still keeps the core identity decision inside an unsupervised clustering stage. Your selected row is stronger than that: it is a direct per-instance linkage between a rendered chevron and a concrete `match_events` row. When the system already has a high-confidence event identity in some frames, best practice is to **treat those observations as seeds or tracklets**, then associate ambiguous observations to those seeded event identities. In sports-specific MOT, the same principle shows up as a move away from unstable image-space tracking toward more structured spaces; FieldMOT improves broadcast sports tracking by shifting from "track-then-register" to "register-then-track," using field-space information to stabilize association across noisy views. Your hockey-space coordinates are the equivalent structured space, so the matching logic should live there, not in greedy pixel clustering.

The best design, then, is a **hybrid**:
- first, create **event-owned tracklets** from frames where `selected_event_index` points at a known event;
- second, run **rectangular one-to-one assignment** for leftover chevrons against candidate events or candidate event-tracklets inside a local temporal window;
- third, only for observations that cannot be attached to any seeded event, create provisional clusters in **space-time**, not in space alone.

The assignment step should use a cost matrix with hard gates on impossible matches and softer costs on plausible ones. The Hungarian-style assignment exposed by SciPy's `linear_sum_assignment` is a direct fit here because it solves minimum-cost bipartite matching and supports rectangular matrices, so unmatched chevrons or unmatched events are naturally allowed.

In practical terms, I would not let two observations ever share a provisional cluster if their event clocks differ by more than a small tolerance, even when their x/y are nearly identical. Spatial collisions are common in sports UIs because icons are quantized and camera geometry is repetitive; **time and identity metadata are what separate "same place, same event" from "same place, different event."** That is why a hybrid is better than pure event-first or pure clock-aware clustering: use the reliable per-instance cue wherever it exists, and use multi-cue assignment only where it does not.

- Wojke et al., *Deep SORT*. https://arxiv.org/pdf/1703.07402.pdf
- SciPy documentation for `linear_sum_assignment`. https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.linear_sum_assignment.html
- Chen et al., *FieldMOT*. https://openaccess.thecvf.com/content/CVPR2025W/CVSPORTS/papers/Chen_FieldMOT_A_Field-Registered_Multi-Object_Tracking_for_Sports_Videos_CVPRW_2025_paper.pdf

**Concrete recommendation for this codebase.** In `inventory_consensus_match.py`, replace the current "greedy pixel-space cluster, then majority-vote event attribution" flow with a three-stage matcher. Stage A should ingest frames where `selected_event_index` is present and create **seeded observations keyed by `match_event_id`**; compute a robust per-event centroid summary in hockey space from those seeded observations. Stage B should collect all non-seeded chevron observations in a short window and run a **cost-matrix assignment** to seeded events using at least these terms: hockey-space distance, absolute event-clock delta, actor equality or actor-similarity penalty, and optional panel-row consistency. Use `scipy.optimize.linear_sum_assignment` for the 1:1 step. Stage C should be a fallback only for genuinely unseeded events, and that fallback clusterer should run in `(x, y, clock_seconds)` rather than `(pixel_x, pixel_y)` alone. I would also log an "assignment margin" diagnostic so QA can see when the best and second-best event matches were too close to trust.

**Expected impact on the relevant layer.** This is the single change in your stack with the clearest direct path to **L2 improvement right now**. Given your six collision pairs on match 463 and the fact that the current failure is specifically an association/ID-switch problem, I would expect a well-implemented event-first hybrid to move **L2 on match 463 from 91.8% into roughly the 95–97% range** as a first pass, with the exact gain depending on how many downstream deductions are caused by those swapped pairs rather than by OCR noise.

## Anchor-text gate calibration for screen classifiers

**Question.** How should the HSV-plus-OCR anchor gate be tuned when false negatives and false positives have very different costs?

**Synthesised answer.** The strongest transferable idea here comes from **cascade classifiers**: if an early or intermediate stage can create unrecoverable false negatives, it should be tuned to preserve recall and push hard rejection later or into a richer decision rule. Viola and Jones explicitly describe setting stage thresholds on validation data so that a stage hits an aggressive detection target while still removing a useful fraction of negatives; their example first stage detects all faces while still rejecting many non-faces. That is much closer to your problem than any fixed substring heuristic. In your pipeline, the hard requirement that a tiny OCR ROI must contain an exact anchor substring is functioning like a brittle cascade stage, and because demotion goes straight to `unknown_screen`, those misses are unrecoverable at L1.

For the recall-versus-precision trade-off, the right practice is to **optimize an explicit operating objective**, not to hand-tune "looser" or "tighter" anchors by feel. The scikit-learn threshold-tuning guidance is very clear that the default classification threshold is usually not optimal once costs are asymmetric, and that the threshold should be selected against a business metric or cost function using validation data and cross-validation. In your case, the asymmetry is especially sharp: a false positive scoreboard frame is annoying but can often be filtered later, while a false negative real loadout card makes recall unknowable and can erase an entire derived row. That means the gate should be chosen by sweeping a continuous score against a labeled validation set and optimizing a cost function that prices false negatives for `player_loadout_view` substantially higher than false positives.

That last sentence matters because, as currently described, you do **not yet have a continuous gate score**—you have a boolean substring test. Calibration methods such as Platt-style sigmoid mapping or temperature scaling are only useful if the model exposes a score that can be calibrated. Guo et al. show that simple post-hoc calibration can work extremely well and that **simple calibrators outperform more flexible ones on modest validation sets**, with temperature scaling being especially efficient; but the prerequisite is a score, not a yes/no rule. So the first step is to turn the gate into a score such as: normalized fuzzy anchor similarity, OCR confidence on the best matching token, OCR text length, HSV margin to runner-up, and perhaps a binary "anchor lexeme family present" feature. Once you have that, a tiny post-hoc calibrator is reasonable; before that, calibration is mostly ceremony.

Time context is also worth using. Sports-video structure work has repeatedly improved classification by combining simple visual features with **domain knowledge and temporal dynamics**, often via HMM-style sequence models or dynamic programming. You do not need a full learned HMM to benefit from that lesson. A lightweight prior or transition table is enough: if the segment is in the pre-game window or in a roster/loadout flow, lower the acceptance threshold for `player_loadout_view`; if the system is in a live-play section where scoreboard-like negatives dominate, require stronger fused evidence. A short hysteresis rule such as "one strong positive lowers the threshold for adjacent frames in the same short segment" is fully consistent with the temporal-state literature and much cheaper than training anything large.

The practical answer to your "published thresholds / heuristics" question is therefore **no universal thresholds**. The published pattern is per-stage operating points chosen on validation data for the target cost profile. Confidence calibration is **not overkill once you have labels and a score**, but it is not the first thing to do. The first thing to do is build a small labeled set of true loadout cards and confusing scoreboard negatives, then replace the hard anchor condition with a scored gate whose threshold is chosen against explicit recall/precision cost.

**Citations.**
- Viola and Jones, *Rapid Object Detection Using a Boosted Cascade of Simple Features*. https://www.cs.cmu.edu/~efros/courses/LBMV07/Papers/viola-cvpr-01.pdf
- Guo et al., *On Calibration of Modern Neural Networks*. https://proceedings.mlr.press/v70/guo17a/guo17a.pdf
- scikit-learn example, *Post-tuning the decision threshold for cost-sensitive learning*. https://scikit-learn.org/stable/auto_examples/model_selection/plot_cost_sensitive_learning.html
- Xie et al., *Structure analysis of soccer video with domain knowledge and hidden Markov models*. https://www.ee.columbia.edu/~xlx/research/pub/prl-04.pdf

**Concrete recommendation for this codebase.** In the pass-1 classifier code that currently computes HSV argmax and then applies the anchor-text hard gate for the predicted class, replace the boolean gate with a **fused gate score** and move the threshold definition into `tools/game_ocr/game_ocr/configs/classifier/nhl26.yaml`. Add fields such as `anchor_lexemes`, `fuzzy_min_score`, `pregame_bias`, and `liveplay_bias`, rather than only a literal substring. Then create a tiny calibration/eval artifact, for example `calibration/labels/screen_gate_eval.csv`, containing labeled positives and hard negatives. Use that set to fit either a one-dimensional logistic calibrator or a very small logistic regression on features like HSV top-1 score, HSV margin, fuzzy anchor similarity, OCR token confidence, and OCR text length. Finally, add a short temporal prior in the screen-segmentation pass: if the segment is in a pre-game or roster window, lower the acceptance threshold for loadout; if the segment is in gameplay, raise it.

**Expected impact on the relevant layer.** This change is mainly about **L1 observability and L1 recall on `player_loadout_view`**. Right now, that class is effectively unmeasurable, which makes every downstream judgment shaky. Once you have labels and a scored gate, I would expect the first iteration to move the affected class from "unknown recall" to a measured operating point that is probably in the **mid-to-high 90s on the labeled eval set**, especially in pre-game windows where temporal priors are strongest. If missing loadout cards are a real contributor to `match_shot_type_summaries` or other derived-table gaps, this also has a plausible **L3 upside of several points**, but I would not promise 99% from this change alone without the corpus growth described below.

## Single-centroid versus multi-prototype class models

**Question.** Is one HSV centroid per class still appropriate, or should multimodal classes move to nearest-of-K prototypes?

**Synthesised answer.** A useful nuance from the literature is that **single histograms are not automatically bad**. Schroff, Criminisi, and Zisserman showed that compact single-histogram class models can equal or even outperform exemplar-based alternatives when the class is sufficiently compact and the distance measure is appropriate. So the broad histogram-based approach you have now is not an obviously wrong foundation, and there is no literature-based reason to throw it away just because it is simple.

The problem is that your `player_loadout_view` class is almost a textbook case of **within-class multimodality**. The visual variations you named—player photos, palettes, X-Factor icons, and per-player card art—are exactly the sort of within-class subclusters that multimodality papers warn about. Wan et al. show that when classes contain multiple internal modes, treating them as one unimodal cloud can hurt classification, while explicitly modeling the subclasses or clusters improves performance; they also report that performance is best when the model's number of modalities is close to the true number in the data. That is directly relevant to a screen type that has ten distinct card variants per match.

Given your scale and constraints, the literature-backed practical answer is **nearest-of-K prototypes before Gaussian mixtures**. A per-class K-prototype model keeps everything interpretable, preserves your current fast histogram pipeline, and is cheap to evaluate on an RTX 3060 or even CPU. By contrast, the scikit-learn mixture-model documentation is candid that Gaussian mixtures become fragile when there are not enough points per component, because covariance estimation can become singular and model selection by BIC is only theoretically well behaved when there is a lot of data. With only 30–100 samples per class and 192 histogram bins, a full MoG is much harder to justify than a few prototypes.

The best sweet spot is therefore not a single global K, but a **per-class small K chosen on held-out data**. The multimodality literature does not support a universal "K=3 for everything" rule; it supports matching the number of modeled modes to the true modes in the data. Practically, that means sweeping a tiny range such as `K ∈ {1,2,3,4}` per class, measuring grouped validation performance, and using silhouette analysis only as a sanity check for whether the class genuinely wants multiple clusters. My expectation is that most of your stable screen types will stay at `K=1`, while `player_loadout_view` is the obvious candidate for `K=2` or `K=3`.

So the practitioner consensus for your regime is: **keep the hand-engineered descriptor, add a few prototypes where the class is truly multimodal, and only escalate to mixture models if prototypes fail in validation**. A tiny CNN encoder is not the right first move here, because the literature already gives you a lower-risk mechanism for handling multimodality and your current bottleneck is more likely class representation than representational capacity.

**Citations.**
- Schroff et al., *Single-Histogram Class Models for Image Segmentation*. https://www.robots.ox.ac.uk/~vgg/publications/2006/Schroff06/schroff06.pdf
- Wan et al., *Within-class Multimodal Classification*. https://pureadmin.qub.ac.uk/ws/portalfiles/portal/247488751/Wan2020_Article_Within_classMultimodalClassifi.pdf
- scikit-learn user guide, *Gaussian mixture models*. https://scikit-learn.org/stable/modules/mixture.html
- scikit-learn example, *Selecting the number of clusters with silhouette analysis on KMeans clustering*. https://scikit-learn.org/stable/auto_examples/cluster/plot_kmeans_silhouette_analysis.html

**Concrete recommendation for this codebase.** Modify `calibrate_classifier` so that `tools/game_ocr/game_ocr/configs/classifier/nhl26.yaml` can store **multiple prototypes per class**, not only one centroid. For example, allow `player_loadout_view` to have `prototypes: [...]`, each with a histogram and optional metadata such as `source_fixture` and `weight`. In the pass-1 classifier scoring function, replace "cosine similarity to class centroid" with "maximum cosine similarity to any prototype in the class," or a smoothed variant such as a top-2 average if you want slightly less brittleness. Choose K per class using grouped validation over matches or fixtures, starting with `K_max=3`. I would explicitly **not** implement a full GaussianMixture first. If you want a probabilistic experiment later, let a constrained mixture model suggest K during calibration, but keep nearest-prototype inference in production.

**Expected impact on the relevant layer.** On its own, this is likely a **moderate L1 improvement**, not the single biggest lift, because your current hard anchor gate can still demote a correct color-class decision. I would expect roughly a **1–3 point macro-recall gain across screen classes as a first result**, with a larger class-specific lift on `player_loadout_view` if those fixtures are currently being averaged into an overly generic centroid. In other words: this is probably necessary for a robust classifier, but it is most valuable **after** the gate is turned into a scored, calibrated decision rather than a literal substring filter.

## Operator-confirmed labeling protocols for fixture-corpus growth

**Question.** What human-in-the-loop labeling loop is best at your scale, given a five-minute-per-match budget?

**Synthesised answer.** At this budget, the literature strongly favors **active sampling over random labeling**. Settles' survey makes uncertainty sampling and query-by-committee the two most practical families: label the items closest to the current decision boundary, and label the items where competing models disagree most. Your pipeline already has a natural committee: HSV color vote, OCR anchor gate, temporal context prior, and downstream parser consistency. Frames where these disagree are exactly the kind of high-information candidates that active-learning theory says should be surfaced first.

Because you are a single operator, classical inter-annotator agreement is not directly available, but the reliability literature still matters. Artstein and Poesio emphasize that agreement studies are about showing that the labels are reproducible under the guideline set, not merely that labels exist. For a solo workflow, the closest operational equivalent is **periodic blind re-labeling of a small frozen slice**—for example, thirty old frames every few matches—and then computing a consistency score such as Cohen's kappa or Krippendorff-style agreement. That gives you an early warning when the labeling policy is drifting even though the annotator is the same person.

For reproducibility, the core practice is to **version data, labels, and calibration artifacts together**. DVC is one mature way to do that in Git-based ML projects: it tracks data and model artifacts with small metadata files, keeps code and data versions aligned, and supports reproducible checkout of exact historical states. For a single-user internal system, you do not have to adopt all of DVC on day one, but you should absolutely adopt the same principle: every recalibrated `nhl26.yaml` or screen-classifier artifact should point to an immutable label manifest and a specific code revision.

For CI, your instinct about per-class gates is correct. The right regression checks are **class-specific precision, recall, F-score, and support**, not only aggregate accuracy, because a rare but important class can regress silently while overall accuracy stays flat. The scikit-learn metrics API directly supports per-class reporting, including class-specific support and multiple averaging modes, which makes it suitable for a frozen evaluation split in CI. In your case, `player_loadout_view` recall and `unknown_screen` rate should be treated as first-class gates rather than secondary diagnostics.

The best workflow for your scale is therefore compact and disciplined: sample only the highest-value frames, keep labels append-only and reproducible, measure your own label consistency over time, and fail CI on class-specific regressions. That is enough to make L1 measurable and to keep the classifier from regressing as the corpus grows from two matches to a season.

**Citations.**
- Settles, *Active Learning Literature Survey*. https://burrsettles.com/pub/settles.activelearning.pdf
- Artstein and Poesio, *Inter-Coder Agreement for Computational Linguistics*. https://aclanthology.org/J08-4004.pdf
- DVC documentation, *Get Started with DVC*. https://doc.dvc.org/start
- scikit-learn documentation for `precision_recall_fscore_support`. https://scikit-learn.org/stable/modules/generated/sklearn.metrics.precision_recall_fscore_support.html

**Concrete recommendation for this codebase.** Add a new CLI, for example `tools/game_ocr/game_ocr/annotate_segments.py`, that consumes `segments.json` and ranks candidate frames by label value. The ranking order should be: first, disagreement cases (`color_class != final_class`, anchor rejected a high HSV score, or temporal prior contradicts visual score); second, near-boundary cases (small HSV margin or calibrated gate score near threshold); third, segments associated with downstream missing rows or known event-matcher failures; and finally a small random sample to catch blind spots. Store labels in an append-only manifest such as `calibration/labels/frames_vYYYYMMDD.csv` with fields like `match_id`, `frame_time_ms`, `image_sha256`, `screen_type`, `split`, `annotator`, and `notes`, and keep the PNGs under `calibration/extras/<class>/`. Add a frozen evaluation manifest and a CI script—something like `tools/game_ocr/game_ocr/eval_screen_classifier.py`—that recalibrates, scores the frozen split, and fails if critical classes regress.

**Expected impact on the relevant layer.** This is the change that turns **L1 from n/a into a controlled metric**. It will not immediately add large points to L2 or L3 by itself, but it changes the whole optimization loop: after this, Q2 and Q3 stop being blind tuning exercises and become measurable improvement work. The immediate impact is therefore best expressed as **observability and regression control**, with smaller iterative gains—often a point or two per cycle—coming from the fact that you will finally know which classifier changes helped and which only moved anecdotes around.

## Prioritised recommendations

1. **Rewrite chevron matching as event-first seeded assignment with Hungarian fallback.** This is the highest-confidence route to an immediate L2 improvement because it directly attacks the current cluster-conflation and swap failure mode, and it aligns closely with the tracking literature's standard answer to ID-switch problems: strong cues first, weaker cues second, explicit assignment instead of spatial merging.

2. **Build the labeling and evaluation loop before doing more classifier retuning.** Right now the biggest classifier problem is not just performance; it is that `player_loadout_view` recall is unknowable. A five-minute active-labeling loop plus frozen eval split will make Q2 and Q3 testable and will stop future regressions from hiding behind overall accuracy.

3. **Replace the hard anchor substring gate with a scored gate plus temporal prior, then calibrate its threshold.** Among classifier changes, this is the highest-leverage one because the current boolean gate creates unrecoverable false negatives. Once labels exist, threshold tuning against an explicit cost function is the right way to recover recall without flooding the pipeline with scoreboard false positives.
